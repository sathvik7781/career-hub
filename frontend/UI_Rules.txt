=========================================================
CAREERHUB ENTERPRISE UI RULES
=========================================================

This project uses a centralized design system defined in index.css.
All UI must strictly follow these rules.

DO NOT bypass the system unless absolutely necessary.

---------------------------------------------------------
1. COLOR USAGE RULES
---------------------------------------------------------

Use ONLY design tokens.

Primary Color:
- var(--color-primary-500/600/700)

Secondary (Accent):
- var(--color-accent-500/600)

Background:
- bg-app
- bg-surface

Text:
- text-primary
- text-secondary
- text-muted

Borders:
- border-app

❌ DO NOT use:
- random Tailwind colors (bg-blue-500, text-gray-700, etc.)
- inline hex values
- hardcoded rgba colors

---------------------------------------------------------
2. BUTTON RULES
---------------------------------------------------------

Use:
- btn-primary
- btn-secondary

Primary buttons = main actions (Save, Submit, Create)
Secondary buttons = cancel, back, neutral actions

❌ DO NOT:
- create custom button styles per page
- use raw Tailwind button classes
- override gradients manually

---------------------------------------------------------
3. INPUT RULES
---------------------------------------------------------

Use:
- input-field

All inputs must:
- Have consistent radius
- Have focus ring
- Follow light/dark support

❌ DO NOT:
- create custom border or padding
- manually apply focus:ring utilities

---------------------------------------------------------
4. CARD RULES
---------------------------------------------------------

Use:
- card

All content containers must use .card
Cards must contain:
- Proper padding (p-6 recommended)
- Clear section spacing

❌ DO NOT:
- create shadow-md shadow-lg randomly
- manually apply rounded-xl inconsistently

---------------------------------------------------------
5. TYPOGRAPHY RULES
---------------------------------------------------------

Headings:
- heading-xl → Page titles
- heading-lg → Section titles
- heading-md → Subsection titles

Descriptions:
- text-secondary
- text-muted for subtle content

❌ DO NOT:
- manually set font sizes with text-3xl, text-2xl everywhere
- override font-weight randomly

---------------------------------------------------------
6. SPACING RULES
---------------------------------------------------------

Use:
- page-container → Main layout wrapper
- section-spacing → Between major sections

Maintain consistent vertical rhythm.

Avoid random margin stacking like:
- mt-7, mb-9, etc.

Use Tailwind spacing scale properly:
- 4, 6, 8, 10, 12

---------------------------------------------------------
7. SHADOW RULES
---------------------------------------------------------

Shadows are controlled via:
- card
- btn-primary
- btn-secondary

❌ DO NOT manually use:
- shadow-xl
- shadow-2xl
- custom shadow utilities

---------------------------------------------------------
8. DARK MODE RULES
---------------------------------------------------------

All UI must support dark mode automatically.

Do NOT manually write:
- dark:bg-gray-900
- dark:text-gray-100

Use token-based classes only.

---------------------------------------------------------
9. ICON RULES
---------------------------------------------------------

Use:
- lucide-react icons only

Icon size:
- 16px (w-4 h-4) → small UI
- 20px (w-5 h-5) → nav / buttons
- 24px (w-6 h-6) → section headers

Icons must align with text using:
- flex items-center gap-2

---------------------------------------------------------
10. ANIMATION RULES
---------------------------------------------------------

Use:
- animate-fadeIn
- Framer Motion (subtle transitions only)

❌ DO NOT:
- add bounce/spin animations
- use distracting effects

Enterprise UI must feel calm and confident.

---------------------------------------------------------
11. COMPONENT STRUCTURE RULES
---------------------------------------------------------

Every page must follow:

page-container
    → heading-xl (page title)
    → section-spacing
        → card
            → heading-md
            → content

Avoid deeply nested random divs.

---------------------------------------------------------
12. CONSISTENCY PRINCIPLE
---------------------------------------------------------

If a UI element exists once,
it must look identical everywhere.

No per-page customization unless:
- It improves clarity
- It follows design tokens

---------------------------------------------------------
13. FUTURE SCALABILITY RULE
---------------------------------------------------------

When creating new components:

- Reuse design tokens
- Extend system utilities
- Do NOT invent new visual styles

Enterprise design = predictable + consistent.


=========================================================
CAREERHUB ENTERPRISE UI RULES (WITH RESPONSIVENESS)
=========================================================

This project uses a centralized design system defined in index.css.
All UI must strictly follow these rules.

Enterprise UI = Consistent + Responsive + Predictable.

=========================================================
0. RESPONSIVE PHILOSOPHY
=========================================================

Mobile First Approach.

Always design in this order:
1. Mobile (default)
2. Tablet (md:)
3. Desktop (lg:)
4. Large Desktop (xl:)

Never design desktop first.

Breakpoints:
- sm → 640px
- md → 768px
- lg → 1024px
- xl → 1280px

Avoid overusing breakpoints.
Use only when layout truly changes.

=========================================================
1. LAYOUT RESPONSIVENESS RULES
=========================================================

Use container system:

<div class="page-container">
    max-w-7xl mx-auto px-4 sm:px-6 lg:px-8
</div>

Rules:

✔ Padding must scale with screen size
✔ Content must never touch screen edges
✔ Avoid fixed widths (w-96, w-[800px], etc.)
✔ Use max-w-* not fixed widths

Example:

<div class="max-w-2xl w-full">

=========================================================
2. GRID SYSTEM RULES
=========================================================

Default pattern:

grid grid-cols-1 md:grid-cols-2 lg:grid-cols-3 gap-6

Rules:

✔ Mobile → Always 1 column
✔ Tablet → 2 columns max
✔ Desktop → 3 columns max
✔ Avoid 4+ columns unless data-heavy admin view

Never use:
grid-cols-4 on mobile
hard-coded widths inside grids

=========================================================
3. CARD RESPONSIVENESS
=========================================================

Cards must:

✔ Expand full width on mobile
✔ Maintain comfortable padding
✔ Stack vertically on small screens

Do NOT:
- Force side-by-side cards on mobile
- Use fixed heights

Use:

flex flex-col gap-6
or
grid grid-cols-1 md:grid-cols-2 gap-6

=========================================================
4. FORM RESPONSIVENESS
=========================================================

Forms must follow:

Mobile:
- Single column
- Full width inputs

Desktop:
- Optional 2-column grouping for related fields

Example:

<div class="grid grid-cols-1 md:grid-cols-2 gap-6">

Rules:

✔ Keep form max width: max-w-2xl
✔ Center forms on large screens
✔ Avoid full-width stretched forms on desktop

Never:
- Use 3+ column forms
- Place inputs side by side on mobile

=========================================================
5. BUTTON RESPONSIVENESS
=========================================================

Mobile:
✔ Buttons full width when primary CTA
✔ Stack vertically if multiple actions

Desktop:
✔ Buttons inline when appropriate
✔ Use flex gap-3 for spacing

Example:

<div class="flex flex-col sm:flex-row gap-3">

Never:
- Cramped inline buttons on mobile
- Tiny buttons on touch devices

=========================================================
6. NAVBAR RESPONSIVENESS
=========================================================

Desktop:
✔ Horizontal layout
✔ Inline navigation

Mobile:
✔ Collapsible menu
✔ Slide-down or drawer menu
✔ Icons visible
✔ No horizontal overflow

Never:
- Overflow menu items
- Shrink text too small

=========================================================
7. TABLE RESPONSIVENESS
=========================================================

Tables must adapt.

For mobile:

Option A:
- Horizontal scroll
overflow-x-auto

Option B:
- Card-style stacked layout (preferred for complex data)

Never:
- Force large tables on mobile without scroll
- Shrink font below readable size

=========================================================
8. TYPOGRAPHY RESPONSIVENESS
=========================================================

Heading scale must adapt.

Example:

heading-xl:
text-2xl md:text-3xl

Rules:

✔ Headings slightly smaller on mobile
✔ Avoid huge titles on small screens
✔ Maintain hierarchy

Never:
- text-5xl on mobile
- Compressed tiny text

=========================================================
9. SPACING RESPONSIVENESS
=========================================================

Vertical spacing must scale.

Example:

mt-6 md:mt-8

Rules:

✔ Smaller spacing on mobile
✔ Larger spacing on desktop
✔ Maintain vertical rhythm

Avoid:
- Excess whitespace on small screens
- Crowded layout on large screens

=========================================================
10. IMAGE & MEDIA RESPONSIVENESS
=========================================================

Images must use:

w-full h-auto object-cover

Never:
- Fixed height images
- Stretching images

Avatars:
- w-20 h-20 mobile
- md:w-24 md:h-24 desktop

=========================================================
11. MODAL RESPONSIVENESS
=========================================================

Mobile:
✔ Full width (px-4)
✔ Max height with scroll
✔ Avoid huge padding

Desktop:
✔ max-w-lg or max-w-xl
✔ Centered layout

Never:
- Oversized modal on small screens
- Hidden overflow content

=========================================================
12. DATA DENSITY CONTROL
=========================================================

Mobile:
✔ Simplify layout
✔ Hide secondary info if needed
✔ Use expandable sections

Desktop:
✔ Show full information
✔ Use structured layout

=========================================================
13. TOUCH FRIENDLY DESIGN
=========================================================

Minimum clickable area:
48px height recommended

Buttons:
py-2.5 minimum

Never:
- Tiny icons without padding
- Click targets too small

=========================================================
14. RESPONSIVE ANIMATION RULES
=========================================================

Animations must:

✔ Be subtle
✔ Not cause layout shifts
✔ Be disabled for reduced-motion users (future enhancement)

Never:
- Use heavy transitions on mobile
- Trigger scroll jumps

=========================================================
15. OVERFLOW CONTROL
=========================================================

Prevent:

✔ Horizontal scroll
✔ Content breaking layout
✔ Text overflow

Use:

truncate
break-words
overflow-x-auto (only when needed)

=========================================================
16. ENTERPRISE RESPONSIVENESS CHECKLIST
=========================================================

Before marking UI complete:

✔ Test on 375px width
✔ Test on 768px width
✔ Test on 1024px width
✔ No horizontal scroll
✔ No overlapping text
✔ No clipped buttons
✔ No stretched forms
✔ Navbar collapses correctly
✔ Tables readable on mobile
✔ Modals usable on mobile

END OF RESPONSIVE ENTERPRISE UI RULES
